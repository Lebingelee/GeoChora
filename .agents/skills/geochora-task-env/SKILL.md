## Current construction route

`task_env.make_env(uid, *, config=None, render_mode=None, **kwargs)` is the public registered single-environment factory. The selected references are `pick-cube-p16-reference-v1` and `nut-assembly-outcome-reference-v1`; retired selected UIDs fail explicitly. `TaskArtifactDeclarationV1` declares task semantics and `ReferenceTaskDeclarationV1` binds source references and an optional pure Controller. Compilation does not start a provider. For tasks using the common selected binding path, the registered task supplies `selected_binding(config)` and the existing Env assembles the resolved configuration; task binding internals remain non-public. The Marker example uses the existing assembly compiler for its controller and construction provenance. The scalar environment owner is `task_env.environment.reference_env.SelectedReferenceEnv`; `BaseTaskEnv` and `task_env.tasks.reference_env` are compatibility exports. Empty, Pendulum and TwoWheel use the same episode coordinator with their component RuntimeBoundary; selected reference tasks use RuntimeSession and provider adapters. Sol [accepted the bounded lifecycle migration](../../../docs/module/task_env/v2.1.1/maintenance/reviews/20261105_lifecycle_unification_sol_review.md) at `48401525`; the later [bounded core closeout](../../../docs/module/task_env/v2.1.1/maintenance/reviews/20261105_pre_stage3_closeout_120min_sol_review.md) is accepted at `99de88ab`, and synthetic checks do not establish physical/provider qualification.

Task-specific source/reset/evaluation/Solution behavior stays with its Task Artifact or benchmark owner. Reuse `task_env` owners; do not add another factory, Runtime, Recorder, Controller, or provider abstraction. Keep LIBERO benchmark behavior under `bench_deploy/libero`.

## Bounded reset switching

For PickCube R3 state-only, single environment and gravity compensation off, opt in at construction with `execution.reset_profile="pickcube-state-only-switch-v1"`. Then `env.reset(options={"execution": target})` rebuilds inside the same public Env. The target must name its physics provider and resolves from that provider's defaults; finish the current Recorder before reset. The tested edges are MuJoCo CPU ↔ GeoPhys CPU and MuJoCo CPU ↔ Isaac 6.2 CUDA, plus same-route reset. Observation space stays fixed; `hand_pose` is the ee-frame alias. Explicit seed restarts the Core task-seed stream; None continues it. Pure preflight failure preserves the live episode and stream; failure after replacement begins faults and blocks step until explicit reset/rebuild or close. Owned snapshots remain readable, while old bound commands are rejected. This profile publishes no provider_alias and does not prove borrowed-view support. See the [implemented API and limits](../../../docs/module/task_env/v2.1.1/api/README.md).

## Selected configuration

Selected configuration uses nested `execution`, `episode`, and `task` sections. Precedence is Core → task class → task YAML → caller. Legacy `recipe`/`environment` values and supported flat aliases normalize once; unknown fields, conflicting aliases, task-identity mismatch, and unsupported provider/backend/device or render pairing fail closed. The full renderer contract is `RendererSelectionV1`; selected tasks currently admit only state-only (`renderer-selection-v1`, provider `none`, backend `cpu`, profile `none`, device `null`). Non-`none` selected rendering is rejected, not silently downgraded.

PickCube defaults to `r3_continuous_v1`; `r1` is explicit. The bounded selected provider envelope is GeoPhys CPU and MuJoCo CPU, plus the exact PickCube Isaac Sim 6.2/CUDA PhysX source route recorded in the [matrix](../../../docs/module/task_env/v2.1.0/capabilities/capability-matrix.json). Do not generalize to other tasks/assets or a renderer matrix. The resolved configuration, including renderer selection, flows into construction and record metadata. Missing Controller identity is represented as `null` during pure compilation; this is not execution admission.

Existing MuJoCo CPU Position and leaf candidates resolve execution selection through the same configuration owner and selected preflight; old ExecutionSpec identities remain unchanged. F06 checks target-interpreter dependencies before USD loading. An early rejection explicitly leaves source/Artifact/assessment unevaluated. Query/info/record metadata share the request receipt, including structured H5 metadata; static pending, checked layout facts and unknown native-effective readback stay separate. These are 3a routing contracts, not qualification of unavailable provider environments.

Use the [recording/learning contract](../../../docs/module/task_env/v2.1.0/contracts/recording-and-learning.md) and independent H5 inspection route.
