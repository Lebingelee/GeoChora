# 可仿真资产与场景创建

## 目标

把已确认的需求变成可仿真、可复现的 USD 交付，完成分件、生成、材质、物理配置、装配与技术验收；也接收已有 USD 的检查与修复。

## 使用条件

本 skill 与 `scene-orchestration`、`asset-material-creation` 同级安装。建模使用 Blender；离线核验需要 Python、NumPy 和 `pxr`；物理与最终渲染检查需要 Isaac Sim。生成路线还需要接收方提供生图、TRELLIS.2、UltraShape 和重拓扑服务，按实际路线调用；服务缺失时说明受阻步骤，不自动改用简单几何替代。工具路径和服务地址由接收方环境提供，不依赖原仓库布局。

## 输入

- 资产需求与已确认设计：外观参考、尺寸、功能、安装与交互条件，以及允许随机化的属性和范围。场景中的资产遵循 `scene-orchestration` 已确认的方案。
- 可复用的资产及资料（若有）：USD、Blender 来源、材质与已有检查结果。核对是否满足本次需求，只补齐缺失或受修改影响的部分。

## 输出

- 可加载的资产 USD 及其几何、材质和贴图依赖。

## 工作流

### 1 生成单位与方法

先识别独立物体，再按相对运动划分部件：从连接位置识别承担安装、转动、滑动、扣合或传力的几何结构。连接件有可辨认零件边界时沿安装面分开制作；一体成形时只在剩余主体仍完整且不会切碎同一配合结构的局部过渡处分界；部件整体由配合结构构成或为连续简单形体时，整个部件作为直接建模单位并停止分割。可见外表面（门板、抽屉面、面板）归入其所属主体的生成单位随主体细化，铰链、滑轨等连接件才直接建模。固定附属外形随主体；整体搬运、材料差异与外观细节不增加分件。遇到一体成形连接、分割停止或需借鉴已有生成经验时读取[生成决策案例](references/asset-routing-cases.md)。

| 制作范围与条件                                                   | 生成方法                                                   |
| ---------------------------------------------------------------- | ---------------------------------------------------------- |
| 场地边界、地面、墙体等环境基础几何                               | Blender 构建 → `asset-material-creation` 二维贴图          |
| 连接部分，及满足停止分割条件的整个部件                           | Blender 直接建模 → TRELLIS 独立贴图                        |
| 具有机械关节、功能容腔或开口，或存在局部尺寸与形状配合约束的主体 | Blender 粗模 → UltraShape 细化 → 重拓扑 → TRELLIS 独立贴图 |
| 不满足上述条件的完整独立资产                                     | TRELLIS.2 整体生成几何与贴图                               |

覆盖：可操作资产（门、抽屉、容器）的可见外观与容腔内件、以及用户可见的独立家具走生成路线。简单拟合件仅限：按分件规则直接建模的连接件与五金、环境基础几何，以及杆销、龙头、窗框、固定面板、控制外观等不作为操作目标且无独立外观参考的小件；每个简单拟合件的范围与依据在制作记录中注明。家具主体与关键可见资产不得以简单几何或粗模替代。结构与约束不变时沿用已确定路线，生成质量问题在该路线内修复。

### 2 几何

默认米制、Z 向上，建立时明确原点、前向、实例标识和变体。为需要细化的主体创建粗模，为直接建模单位完成交付几何；简化隐蔽紧固与制造内部细节，保留可见连接、支撑及运动配合。
需要确认关节配合、碰撞或联动能否工作时，用粗模建立局部 USD 按物理配置实际试验。

参考图：优先复用 `scene-orchestration` 已确认的示意图；需要补充视角或重画时遵循同一规则：使用生图工具按已确认的类别、轮廓、材料、颜色、纹理方向和新旧程度准备清晰、均匀照明的图像；每图只呈现本生成单位，保留轮廓、厚度、功能开口与容腔，容腔为空、不含内容物，不混入其他单位、无关物体或假结构。

### 3 后处理

装配检查通过后，主体粗网格与参考图交 UltraShape 细化（num_latents ≥ 8192、steps ≥ 30），恢复米制尺度；闭合多容腔壳体跳过重拓扑服务，直接用 Blender voxel remesh 并减面；其余网格经服务重拓扑后复核连通与配合。随后各单位用自身网格与参考图完成独立贴图，贴图条件图遵循同一参考图规则；直接建模单位的贴图须保留输入几何。互不依赖的单位可并行；修改后只重做受影响单位及后续步骤。

每个生成单位完成细化与贴图后渲染，按“检查与验收”的外观审计与本单位参考图对比；不符时按阶梯重试：提高细化或贴图参数重试一次，再重画参考图生成一次。阶梯用尽仍不符时将该资产标记 failed，按“修复与反馈”处理；不降级、不以简单几何或粗模替代、不进入验收通过结论。

TRELLIS.2 整体生成：按需求准备完整单体外观图，一比一还原项使用指定参考，优先透明背景；结果作为不可拆分的整体资产，仅允许位置、朝向、原点和保持外观可信的整体缩放；保存 GLB、metadata、参考图与参数，在 Blender 导入并核对尺寸、原点和前向。生成结果与参考明显不符时按上述阶梯重试，失败处理相同。

### 4 材质

生成的 PBR 随资产接入，保留 UV、颜色、金属度与粗糙度绑定。新增表面贴图或局部修改调用 `asset-material-creation`。已有生成材质按明确问题修改。

### 5 物理与装配

单位与身份：核对 metersPerUnit、上轴、导出变换与四元数顺序，按实际单位换算几何和物理参数；旋转关节角度使用度，距离按 stage 长度单位，测量注明单位。以最终组合 USD 的属性、relationships 和 prim 路径核对装配；导出、引用或重命名后复查实例与部件映射；共享视觉资源的各实例保持独立物理身份。

碰撞：可活动物体或部件在下列条件下合法：所属动态刚体（非 kinematic）或可变形体下存在启用的碰撞（CollisionAPI 且 collisionEnabled 为真），碰撞 prim 的有效可见性（含祖先）不为 invisible，碰撞包围盒覆盖视觉包围盒；不渲染的碰撞用 purpose="guide" 隐藏。碰撞默认直接由视觉网格承载；mesh 过于复杂或需补全交互细节时可使用独立碰撞节点。一个刚体可包含多块视觉网格与复合碰撞，视觉与碰撞明确归属对应刚体；使用嵌套刚体时核对引擎支持与变换继承。碰撞形状保留操作需要的支撑面、开口、容腔和间隙；动态刚体的原位置不保留静态碰撞副本；固定环境保持对动态物体有效的碰撞。同一资产内各刚体（单物体各组件）之间关闭相互碰撞，以关节运动角度限制作为替代；干涉与穿插检查排除同资产内部件对，只覆盖资产之间及与环境。按尺寸、材料与组成设置质量、惯量和接触参数并说明依据；关节阻尼、摩擦与弹簧按实际结构与运动特性配置。

约束与归属：关节两侧连接实际支撑与运动部件；支撑固定安装时可连接世界并记录对应固定支撑几何，可移动支撑连接其实际刚体。局部锚点与坐标系相对于各自连接的刚体，世界侧使用世界坐标；按实际连接确定轴线、正方向与参考构型，记录零位、允许范围与初始状态。固定在部件上的五金随对应部件运动，连接结构与约束轴线保持一致。物理归属：依据任务所需的交互与实际安装关系配置物体及部件的运动能力。永久静态的物体与部件仅配置启用的 `CollisionAPI`，不施加 `RigidBodyAPI`、`PhysxRigidBodyAPI`、`MassAPI` 或对应刚体属性；已有来源按此归属移除多余配置，不能仅将 `rigidBodyEnabled` 设为 false，也不能以 kinematic 刚体身份替代固定。可动资产配置整体刚体，未固定连接的承载物保留独立刚体；固定资产的柜门、抽屉等关节活动部件保留刚体与碰撞，关节另一侧连接世界；含活动部件的资产保留部件相对运动，固定附件归属对应刚体。由脚本或动画驱动的 kinematic 物体属于可动资产，驱动方式在需求中声明。用刚体近似软质物体时在交付中说明适用范围。

操作验证共同条件：粗模试验和资产测试使用当前局部场景及符合安装关系的支撑，最终场景测试使用完整布局和实际周围物体，记录所用版本与检查范围。经独立测试配置施加有限力或力矩，测试前记录施力上限、目标、完成时限、保持时间及验收阈值；临时驱动与交付配置分开管理，保持交付配置的质量、碰撞和被动阻力；直接设置部件位姿仅用于几何检查。全过程检查连接、运动范围和干涉；几何检查采用连续或记录步长的采样，疑似干涉用实际几何或接触证据确认。单资产测试使用与安装关系一致的支撑与接触；测试副本的支撑只用于复现安装条件。

场景接入：所有资产通过可复用构建函数接入，函数接收实例标识、父节点及尺寸、材质或变体参数，返回实例根节点、语义部件映射和包围范围；实例具有独立标识与变换，可共享只读几何与材质，随机细节保留 seed。修改共享模块或依赖后复查受影响实例。堆放初态须显式配置摆放与接触关系；任务加载后不得通过沉降或预运行修补初态，遵守[回合首帧条款](../scene-orchestration/references/embodied-integration.md#回合首帧条款)。按已确认灯具布置实际 USD 光源；需要选择光源或调光时读取[照明指引](references/lighting.md)。

### 6 检查与验收

检查以 Isaac Sim 加载的交付 USD 为准，覆盖资产本身及其安装条件；背景布局与组合问题见 `scene-orchestration`。交付前按照清单标注 passed、failed、not_executed 或 not_applicable；修改后复查受影响项，沿用其余有效证据。

- **尺寸与标识**：数量、标识、单位、坐标、尺寸及朝向符合需求，明确尺寸用测量核对。
- **部件划分**：网格与生成单位对应，活动部件具有独立身份与变换，改变姿态核对随动归属。
- **网格连通**：生成与细化网格按部件保持连通，无断裂或浮片；副本中归并重合顶点后统计连通分量。
- **安装连接**：固定附件与连接件同安装面实际接触，支撑链完整，无悬空或妨碍配合的穿插。
- **容腔与开口**：容器与抽屉在闭合态具有可用容腔；打开或剖视检查厚度与通达性是否合理。
- **运动配合**：在闭合、初始、开启及中间姿态检查连接与间隙；干涉按本节物理与装配口径判定。
- **物理配置**：按“物理与装配”核对可动/固定归属、碰撞、关节及参数，包括缺失和多余的刚体配置。
- **材质与照明**：材质技术检查见 `asset-material-creation`；直接建模单位核对贴图前后几何一致，在交付 USD 中确认实际光源。
- **复用**：构建函数创建至少两个不同位置或朝向的实例，所用变体分别验证。
- **综合检查**：使用本 skill 的 `scripts/verify_claims.py <asset.usda> <claims.json> [result.json]` 对 USD 进行检查；断言格式及覆盖范围见[断言表说明](references/claims.md)。脚本路径相对于本 skill 目录，USD、断言和结果路径指向本次工作目录。

外观审计：对每个生成单位与关键可见资产，从参考图或已确认示意图列出部件清单（如马桶＝水箱、盆沿、底座、座圈、盖板），渲染交付资产的实际渲染图并与参考图并排，逐项核对部件齐全、轮廓与选定设计特征，写出逐项结论；模糊的整体描述不作为审计结论。最终外观结论与对照图归入验收证据，未解决的外观问题记入 `scene.md`。MCP 服务成功状态、物理、运动与容腔测试通过均不作为外观证据。

图像检查：验收图全部来自 Isaac Sim 加载交付 USD 的实际渲染；Blender 渲染只作过程预览。每次检查先读取覆盖目标的总览或分组图，必检部位看不清时补充近景；已查看且足以支持当前判断的图像直接复用。捕获结果以像素统计与实际查看确认，文件存在或退出码不作成功判据；捕获临时目录使用 ASCII 路径。

### 7 修复与反馈

量化失败项记录对象、实测值、阈值与证据；定位原因后修正几何、物理或配置，按原判据复测，记录修复前后数值与成果版本。几何失败返回可编辑来源并更新后处理与物理配置。未执行或未覆盖的检查单独列明；失败项保留实测结果。

路线失败与 failed 资产：“后处理”中的阶梯重试用尽仍不符、或生成服务无法产出可用结果时，将该资产标记 failed，在 `scene.md` 中说明问题及影响范围，最终未通过项及其证据随验收结果保存。允许带标记交付，不以简单几何、粗模或其他资产顶替，不改写为验收通过。收到影响分件或方法选择的反馈、或完成有复用价值的试验后，按[生成决策案例](references/asset-routing-cases.md)记录适用条件、依据与结果。

### 8 文件与交付

场景交付遵循 [scene-orchestration 的输出目录结构](../scene-orchestration/SKILL.md#输出目录结构)：最终资产 USD 及其几何、材质和贴图依赖归入 `output/assets/<asset_id>/`，完整场景归入对应实例。生成过程中出现不得不报告的问题时写入`output/scene.md`，说明影响范围并引用必要验收证据。完成后，`output/`中的文件不应存在对`src/`中文件的任何依赖。

模型与材质依赖（含 MDL）使用交付目录内相对路径。整理交付目录后，重新加载 USD，确认资产依赖完整且配置有效。
