# v1.1.0 Candidate Capability Matrix

**RELEASE_CANDIDATE — NOT_PUBLISHED**

The sole authoritative candidate matrix for this release cycle is
[`capability_matrix_v1_1_0_candidate.json`](../../module/task_env/capability_matrix_v1_1_0_candidate.json).
It distinguishes `IMPLEMENTED`, `TESTED_BOUNDED`, `QUALIFIED`,
`HISTORICAL_ONLY`, `RETIRED`, `PLANNED`, and `NOT_IMPLEMENTED` without
conflating source presence, bounded execution, or formal approval.

The matrix binds each result to task UID or route, serialized Artifact where
applicable, provider/backend, configuration, exercised source revision, and
evidence identity. The four selected task/provider results are bounded
functional acceptance, not new qualifications. The two NutAssembly providers
retain separate task outcome, Outcome V1 completion, readiness warning, and
strict Expert lifecycle observations.

The previous `capability_matrix_v1_0_1_candidate.json` draft is preserved at
[`archive/capability_matrix_v1_0_1_candidate_historical.json`](../../module/task_env/archive/capability_matrix_v1_0_1_candidate_historical.json).
It is historical review material, not a competing candidate matrix. Its two
NutAssembly H5 digests referred to baseline H5 files; the current matrix uses
the final-source H5 hashes verified against the S2-C2 acceptance report and
retained files.
