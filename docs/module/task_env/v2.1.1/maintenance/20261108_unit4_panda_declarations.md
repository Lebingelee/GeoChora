# Panda fixed-assembly declaration boundary

The exact pinned Panda arm and hand source recipe is declared by `task_env.assembly.panda_fixed_source`. It preserves the existing two-source hash, namespace, fixed mount and tendon checks; the historical fixed-attachment candidate consumes that adapter rather than owning a second source implementation. `AssembledPandaAgent` declares the two assets, named initial state and reference inventory. Its nested effort binding uses the existing controlled-subject compiler and distinguishes the fixed arm from its constrained hand. A bounded MuJoCo diagnostic exercised that binding with one write per interval, while the original source position drives remained enabled.

This is an implementation increment, not a new public task route. The selected PickCube configuration cannot yet select this Robot. Its task scene includes a free cube, whereas the existing fixed-attachment native admission is restricted to the exact two-entity model and rejects free joints. The Agent therefore advertises no selectable generic controller kinds. Two-source PickCube construction, production Controller dispatch, full unit 4 and visible rendering are not established by this increment; the diagnostic result does not claim them.
