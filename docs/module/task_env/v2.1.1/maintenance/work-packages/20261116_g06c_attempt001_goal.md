## 公共语义与实现顺序

1. 第一阶段冻结最小接口并写入API说明：采用现有 `env.reset(seed=..., options={'execution': target_execution})` 表达全批重建，`target_execution`使用既有执行配置字段（provider、interpreter、CUDA设备等），不另造provider别名。无options时行为不变。配置切换仅允许mask省略或全true；部分mask连同切换请求必须在破坏旧batch前拒绝。未知options、改变B/task/Robot/action或obs规格、变更renderer/相机规格均明确拒绝。本包不支持单slot后端切换。
2. 用共同resolver从目标provider合法默认值解析路线，保留Task/Robot/Controller/相机声明；不要将旧provider私有参数盲目传给目标。构建输入保存为声明/解析配置，不持有旧native对象作为配置。不依赖调用者先手工close或创建另一个Env。
3. 重建前完成可纯验证的provider、schema和固定renderer兼容性检查，失败不消耗旧RNG、不改变旧状态，旧Env可继续step。native构建时才发现的问题不能伪称已预验证。
4. 破坏性阶段先停止旧batch、完成必要GPU同步并释放其资源，再构造目标，避免8GiB显存上两个完整batch同时驻留。跨进程provider重启沿用既有worker/IPC owner；不创建第二控制进程体系。目标reset成功才发布新binding/metadata/episode；所有slot进入新episode。
5. 关闭旧batch后的构造或reset失败：清理所有已创建资源，将同一Env置于明确faulted状态，step/render/state禁止继续使用旧数据；close可重复。无需重新构建旧backend做昂贵回滚。报告区分“预验证拒绝保持旧Env”与“破坏阶段失败关闭后faulted”。
6. `id(env)`贯穿A→B→A不变。固定renderer指创建时选定的Rasterizer实现/配置、相机名和外参/分辨率/网格合同不变；绑定旧物理场景的GPU资源可销毁并重建，必须报告实际资源生命周期，不声称同一个native framebuffer永远不变。不得偷偷改用Isaac RTX或MJWarp renderer通过切换。
7. 每次重建产生可区分的materialization/generation，不能因重新创建对象generation回到初值使旧绑定复活。旧Robot view、已准备的reset selection/控制绑定、借用state/frame在相应消费入口明确失效；历史owned快照仍可读，但不能冒充新generation输入。普通无身份action tensor是数值输入，可按新schema重新提交，不能假称能检测其来自旧episode。优先沿用已有command类型，不为测试制造新公共命令协议。
8. canonical Controller的旧缓存/pending贡献随旧runtime清理；新runtime第一步不得带旧effort。无状态Controller如实说明，不为“Controller历史”添加虚拟状态；存在状态/队列的现有owner以定向测试验证清理，不引入R3。

## 验收门与最短运行组合

### C1：三后端、两任务的部分reset

B=3，不改provider；使用已完成step后的pre-reset边界为比较基准。覆盖全false、单行、非相邻两行mask，并复用6b有效证据补缺。核对选中行新episode、未选行qpos/qvel/Task计数、下一次相同动作响应以及后续随机采样序列对无reset对照一致。全false不推进物理、不消费RNG或增加episode。

注意Isaac/GeoPhys原生时钟可能是batch共享计数，不能要求为每slot伪造原生clock；检查共享physics无额外step和每slot episode clock。借用缓冲可能因任一行更新而整体失效，应明确期限；未选行物理状态不变与旧borrowed对象有效不是一回事。

PickCube检查未选行相机绑定和采样身份，图像对应同一物理边界；不能因renderer全批重绘就误判native推进。对确定性Rasterizer同配置可直接比较像素；若产生非零变化需先解释实际来源，不能宽阈值覆盖错行。

### C2：错开终止与same-step保留

三后端PickCube在B3通过错开reset制造错开horizon，不改Task成功条件。至少覆盖一行结束、其他行继续及后续另一行结束。独立核对旧终止state/RGB与新首帧，episode/env/materialization身份、时间、reward/done对应；继续step后owned终止图像不被复用buffer改写。复用6b短程物理和读回，不需要完整抓取。终止与截断分支可由既有纯测试补覆盖，不强迫新增native成功抓取。

### C3：两个任务各一条真实 A→B→A

固定B3、CUDA，代表边为 **Isaac→MJWarp→Isaac**，两个任务分别运行；不把两个backend的scalar进程拼成batch。每段都reset、施加非零且不同行动作、核对真实native状态、Task及关闭。三后端部分reset不等于必须做所有后端两两切换矩阵；GeoPhys跨后端切换尚未验证时明确标为未准入，不冒称任意三后端切换支持。

Pendulum无观测相机，固定Rasterizer窗口至少验证切换后显示不额外推进。PickCube保持base/hand各128×128 CUDA uint8、窗口640×480与同一网格声明，三段都有真实状态驱动帧。图像/状态无需跨后端数值相同；必须绑定当前真实行/hand frame，不能复制A帧到B。动作/obs树、dtype/device及B轴固定。

每次目标切换重新开始episode；episode整数若因现有合同重置则必须由generation唯一消歧，不能将新记录接到旧episode。Recorder在切换前正确收束旧generation，在切换后继续或显式开启新record segment，沿用已有记录API，不要求一个H5混装不同物理来源。独立读取三段至少两行的状态和PickCube图像，能追溯A1/B/A2，不靠截图证明切换。

### C4：失效与失败清理

真实A→B→A中保存旧Robot view/state/frame/selection，在第二次回A后仍不能作为当前绑定使用。纯/fake测试覆盖：不兼容请求在破坏前拒绝、worker已创建后构造异常、renderer绑定异常、首次reset异常、清理自身报错和重复close。只针对当前owner实际能触发的路径，不追求任意SDK故障覆盖。

至少在一个真实B3切换流程中，于目标资源已创建之后通过诊断侧受控失败注入验证释放及faulted行为；生产不得增加环境变量后门、monkeypatch通道或专用探针。不要杀任意系统进程。记录本次worker退出/IPC句柄关闭、GPU持有引用和锁释放；driver缓存导致显存不回到启动值不能单凭此判泄漏，也不能只看Python close返回就宣称native释放。

### C5：普通caller与规范收尾

提供一个简洁 `examples/parallel/reconfigure_device.py`，调用公共reset接口完成两任务所需配置选择，不导入诊断包/provider私有成员。其构建与关闭流程复用既有owner。更新API和能力范围，明确支持的切换边、故障语义、固定renderer及snapshot期限。对原host/SB3/device reset签名和6b公共调用做受影响回归。
