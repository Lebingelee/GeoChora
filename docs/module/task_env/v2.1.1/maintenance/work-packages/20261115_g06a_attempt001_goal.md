## 5. 合同与本包实现顺序

1. 完成依赖profile解析与实际caller路由；可执行的环境查询不启动SDK。隔离必要时验证公开CUDA IPC的双向数据、event顺序和close，不将普通配置/元数据查询做成逐步探针。
2. 接通共同构建与device模式。Dict action每叶CUDA float32 `[B,*single_shape]`；obs保留任务树；reward float32 `[B]`、terminated/truncated bool `[B]`。scene／controller／native三个命名空间明确映射，env-local状态不混入render网格偏移。
3. 复用Pendulum注册、原始资产、reset分布、限幅和TaskDefinition；只抽取需共享的公式／参数，tensor实现就近归位。canonical经现有typed control链到native，禁止专用torque旁路。第一条真实链固定MJWarp、B=3、seed73，不以B=1或旧GeoPhys host demo替换。
4. same-step顺序固定：step完成→评价旧transition→保留done行最终obs／已配置图像→mask reset→Controller reset→新首帧→返回。done／reward属旧episode，done行obs属新episode。普通borrowed视图不能当作跨步owned快照；仅复制需要保留字段。每env RNG／episode／clock独立；reset不倒退整个native时钟。
5. Pendulum不创建传感器相机；无窗口时也不建render scene、图像资源或RGB fence。旧task_rgb接口保留；新 `obs["cameras"][name]["rgb"]` 为CUDA uint8，scalar与batch共享配置、后者多B轴。PickCube前置用例验证base／hand的公开挂载意图，不给Robot增加相机质量或碰撞。
6. R0先检查Rasterizer实际公开端口，再做最小真实验证：非零step产生的公开pose→网格visual→窗口或离屏帧；重复render不能推进physics。目标两种真实physics来源，至少先完成MJWarp来源；第二来源优先Isaac。记录GPUframe输出、mount、geometry与内存共存是否成立。只看图变了或registry写parallel=true不算通过。
7. Rasterizer缺少公开设备图像／foreign pose端口时，定位到Core adapter还是GeoPhys上游，并提交精确函数／输入输出／owner建议；本包不改GeoPhys gitlink或用私有字段补洞。MJWarp renderer仅作备选可行性定位，不同时实现两套或私自把RayTracer换回来。
8. 完成受影响旧caller回归、文档与返包。若关键前置门失败，保全真实结果；能独立完成的同包工作继续完成，但不启用不成立的生产交集，不进入6b。
