## 4. 实施顺序与冻结合同

### A. 共同构建、任务与 batch Robot

1. 保持“任务注册→Scene声明→构建→主体绑定→canonical Controller绑定→TaskDefinition”。scene/reset分布/Controller规格/TaskDefinition由单环境和并行共享；provider-specific lowering 合法，公共声明不可分叉成三份任务。
2. action 为 Dict，各叶 `[B,...]` CUDA tensor；obs 保留树结构并前置 B；reward、terminated、truncated 为 `[B]`。实际 dtype、单位、single规格及批量规格从声明产生，禁止在三个 provider 各定义一套动作顺序。保留6a固定B终止树、有效mask、final_info/reset_info、Task metrics、owned快照与故障锁存。
3. canonical 指实际 source-bound 语义通道；Pendulum 为声明关节 effort，PickCube 按实际主体及传动声明解析。不得按“7+2”硬编码／直接把action当ctrl索引。明确关节 effort 与 actuator／tendon effort 的转换和耦合约束、单位与饱和规则；相同公共动作在三后端表达相同物理含义。native drive 与显式 effort 不得无意双重施控。
4. 复用现有 Robot facade 暴露声明主体、嵌套结构、受控关节／通道、frame映射及 CUDA batch 状态；静态模型信息无需复制B份，动态信息带B轴。view引用当前runtime/generation，不另开physics、不缓存旧状态。至少以Pendulum和Panda两种主体证明不是Panda专属接线；不为R3预建未消费的大型模型接口。
5. PickCube device observation/reward/termination使用任务既有公式和参数；tensor化保留任务语义，不按provider分支改奖励。用独立小样本对照现有标量公式，覆盖阈值两侧和姿态／距离等实际项，不要求不同solver逐点同轨迹。reset在现有声明采样协议下处理arm、finger、free cube；不新增环境生命周期。

### B. 原生物理六格，先暴露难点

在大规模渲染前逐格以B=3跑通；建议先复核MJWarp Pendulum共同接线，再完成GeoPhys／Isaac Pendulum设备端口，尽早探明三条PickCube接触与传动缺口，避免最后才发现GeoPhys阻断。

- **GeoPhys：**实际创建 rigid native homogeneous batch，一次native batch step推进所有world；通过公开CUDA端口传入各行control、读取state/pose并按mask reset。现有host桥的逐行打包不可留在device热路径。核对free-body、articulation、手指耦合、桌面／cube接触、world-local接触缓存与reset刷新。场景桌面接触与ground功能分开按实际语义处理，不能以关掉接触获得准入。
- **Isaac：**同一physics owner中创建真实多articulation／多free cube，使用原生batch tensor view；映射env ID到原生实体的顺序不能依赖未经验证的路径枚举。建立碰撞组／过滤和各自环境原点，验证跨环境碰撞隔离；扩大网格间距不是过滤机制的独立证明。reset选定articulation/free body并刷新pose，避免其他行推进或读到旧tensor。复用6a设备发布与共享IPC。
- **MJWarp：**使用原source与mesh解析、合法批量模型／数据布局，检查nq/nv/freejoint与关节映射、actuator gear／tendon／equality等真实声明。free cube必须实际受重力和接触作用，两手指不是仅视觉同步；碰撞mesh与visual mesh分清。不能把Panda替成简化方块或拿单摆精度外推接触正确。
- 三者都保留每world状态与内部原生clock、control interval/substep事实；render/capture/read不额外推进。默认传感器与窗口全关时不分配可选renderer／图像资源；SDK基础依赖若无法完全卸载，应记录真实固定开销。

### C. 图像、真实reset和记录

- 同一Rasterizer接三个provider公开batch pose；网格offset只加一次，物理env-local坐标与渲染world坐标明确。frame四元数顺序、hand相机外参和capture完成边界同源。
- PickCube配置启用base＋hand，`obs['cameras'][name]['rgb']`为owned CUDA uint8 `[B,H,W,3]`；Robot只提供挂载frame／预设，配置决定启用及参数。窗口仅observer，不加入Agent obs；窗口关而sensor开仍采图。Pendulum默认不声明传感器，不为本包性能矩阵添加测试相机。
- 用不同初态／不同行动作及单行／非相邻行reset，在每格实际物理中证实行身份。PickCube核对hand camera随该行真实末端运动；同一时刻图像要对应同一行state和clock，禁止复制world0再移动视觉几何冒充batch。
- 每格至少一次真实masked reset、错开episode的same-step autoreset；有限horizon可触发真实truncation，不伪改task predicate制造成功。terminated纯语义阈值与双done合同可用fixture补测，但不能冒称native任务成功。未选行以匹配动作的无reset对照核验，正常step期间本可运动，不错误要求它们数值静止。
- 复用VectorTransitionRecorder，显式选至少两行记录真实状态／动作／episode；PickCube包含真实base/hand终止图与新首帧。独立reader核对同次公共返回值与H5全部已记录边界；每provider至少一个PickCube真实episode记录，不能用6a受控图像fixture替代。默认训练路径关闭记录和CPU导出。
- 本包要补足真实backend reset功能，不把必需实现全部推给6c；6c负责完整mask故障矩阵、跨generation失效和同一Env固定renderer A→B→A总验收。

## 6. 性能矩阵、数据传输与资源预算

当前机器约8 GiB VRAM、16 GiB RAM；后端串行运行，不同时保留三套native上下文。共享native锁沿用既有Harness；持锁前核对其他进程，不终止他人任务。

1. 每个provider：PickCube `(sensor off/on) × (window off/on)`四项；Pendulum无sensor，只测window off/on两项。三provider总18项。相机固定base＋hand各128×128，observer640×480；物理dt/substeps按模型冻结，同档窗口／传感器开关不能改变动作序列或physics参数。
2. B=3 correctness通过后，从B=16开始。每个task×provider独立判断：当前档无传感器无窗口完整control step稳态频率 **>10 Hz**、正确性仍成立且资源允许，才进入下一档256，再用256同条件决定4096。不以一个provider的结果替另一个扩容；无状态链阈值则不扩容。
3. 每个获准档分别测该任务的传感器／窗口组合；渲染组合资源不够可明确RESOURCE_LIMIT并报告，不阻止资源允许的纯状态更高档，也不偷偷只渲染部分env。记录实际显示／采集数量、频率及是否限帧；不能将降采样结果混为同配置性能。任一B=16必需组合未运行/失败则本包相应门未通过；较大档条件不满足是CONDITION_NOT_MET，不是伪PASS或必然失败。
4. 控制Hz用同步边界下整批public step墙时测量，包含action交付、native子步、Task、obs及承诺的sensor捕获；env transitions/s=B×control Hz。window FPS、sensor Hz、仿真dt、物理子步Hz、初始化／编译耗时、稳态耗时分列。预热至少20 control steps，测量至少100步且至少10秒；有硬限时不能完成则写样本不足，不外推。禁用Recorder性能与显式录制性能分开。
5. 记录整卡VRAM与进程峰值、进程组RSS、启动固定开销和随B增长的增量；Torch allocator数字不能代表SDK总占用。GPU内部复制／转换／同步、CPU小mask读回、窗口present、显式H5导出列入传输账；少量控制信息允许，常规全量action/state/图像host往返不允许。初始化CPU解析资产与热路径分开计。
6. 预算：预计活动8～12小时，timebox12小时；锁／外部等待另记、累计上限90分钟。累计native运行墙时上限4小时；每run最多15分钟、2000 control intervals，实际batch与world子步分别记账。小档先20步排错再延长；规模档先按已测固定／增量占用估算再分配。建议VRAM工作上限6 GiB、进程组RAM12 GiB，且实时可用量更严者优先；预算不足不得杀占用进程或突破上限硬跑。
7. 每run证据≤256 MiB、整包≤4 GiB；规模测量不保存所有帧／状态，计时数据与稀疏见证即可；小B正确性／记录run保留完整被读回边界。不通过减少所需证据隐藏失败。

一次attempt可多次修复和验证，普通失败不立即结束。没有新假设的同根因重复失败先归因；真正越界／资源不足／上游不可行时保全现状，完成独立可推进部分后返PARTIAL。不得因首轮失败自行宣布GeoPhys可选或冻结一个更弱任务。
