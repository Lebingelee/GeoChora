## 5. G06应继承的限制与本阶段新工作

以下是[G06原范围](../../goals/06-parallel.md)的实现输入，不作为返工G05的附加门：

1. 四个正式UID目前在不支持的batch请求上于资源创建前拒绝。旧vector注册／示例不证明其batch支持；6a需真正对接env ID、batch axis、每slot episode／clock／RNG、mask及固定schema。
2. 至少两个物理后端、至少一个native batch仍是6b目标。执行包应选定可行Task／Controller／provider／renderer交集和资源预算；不能从四个task RGB登记项推导任意batch或N个串行Env就是native batch。
3. renderer从创建到close固定；6c切换backend必须保留该renderer并对不兼容组合提前拒绝。运行中renderer切换仍未排期。
4. Isaac受测frame mount不扩展至MuJoCo／GeoPhys；GeoPhys task与observer受共享framebuffer分辨率约束。部分reset必须避免污染未选slot的相机、历史、pending贡献和RNG。native epoch与episode clock应分别继承，不假设SDK原生时钟为0。
5. RGB当前为owned host copy；batch GPU路径、borrowed buffer期限、终止obs／新episode首帧及Recorder每slot身份均须在6a～6c实现及验证，不由标量G05自动获得。颜色primaries未校准、SDK关闭限制和startup/reset unknown按原范围保留。
6. G06必须继承本次`7f8796b4`的有意生产成果；当前尚在G05阶段分支，不应从落后的develop直接启动后丢失优化。阶段分支／集成、native窗口及具体执行包另按既有流程确定，本轮不checkout／merge／push／tag／发布。

不要求为启动G06先完成RGB完整Solution、全provider×renderer×seed矩阵、native sequence、D0或新Qualification；G07最终矩阵和未排期能力仍留原位置。
