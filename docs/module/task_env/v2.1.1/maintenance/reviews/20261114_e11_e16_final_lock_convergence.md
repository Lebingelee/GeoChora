# 最后一轮共享锁收敛

本轮当前受支持的运行入口为 `builtin_example_validation.py` 的正式示例监督器，以及三个 v2.1.1 计划驱动 CPU probe。正式示例只打开已存在的 `workspace/locks/shared_native_execution.lock`，不创建锁；如果历史兼容硬链接存在则核对同 inode，取得锁后与监督过程中检查路径身份，检测到变化时终止 worker 并判定无效。旧别名缺失时不再阻止新的正式示例。probe 的新计划必须明确列出规范锁，按 inode 去重，取得时拒绝缺失、符号链接或路径替换；冻结旧计划不被改写，未列规范锁的旧计划拒绝执行。

F05 N1／native、R04b、R05b、R06b 历史 native supervisor 的公开执行入口和九个相关旧计划生成入口已明确退役，失败关闭；F05 旧计划／读回代码的锁打开不再使用创建模式，R04b/R04c 同样不创建锁。原历史计划、收据和冻结源码身份不改写。R04b/R06b 的历史假监督测试核心保留，要求显式注入 fake 进程函数；它们是测试辅助接口，不作为受支持的生产执行入口，也不是针对任意恶意 Python 调用的隔离边界。

新旧路径目前仍是同 inode 硬链接，旧链接没有删除。协议只覆盖本次列出的受控运行者；其他 checkout、旧外部副本及恶意或非合作文件替换不在保证范围。运行中的正式示例按监控循环检查路径变化，并非原子地禁止其他进程在任意时刻替换路径；probe 仅在取得锁时检查，不能声称能阻止运行期间的非合作替换。

受 pure guard 的定向回归：20 项锁与 worker 退休测试及 R04b 锁超时／零启动节点通过。完整两个测试文件还存在两个与本次 diff 无关的历史 API 漂移失败：测试引用当前不存在的 `build_reference` 和 `ISAAC_PYTHON`；不能称整个文件全绿。R06b 历史 fake 节点因旧的 `attached_leaf_candidate` 模块缺失无法收集，不能记为通过。真实 worker 及最终项目接收另行记录。
