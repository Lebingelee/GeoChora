# Core ↔ physics provider 协议草案

状态：`DRAFT_FOR_DISCUSSION`；1c 冻结。扩展现有 RuntimeSession／admission／adapter，不另建 provider 抽象层。操作名描述职责，具体签名由现有公开入口收敛。

## 责任

Core 拥有任务语义、需求汇总、初始化采样、生命周期调度、Controller、观测组合、记录及评价。Adapter 拥有原生场景翻译、native 对象映射、公开调用、同步和自己创建的资源。Provider 项目拥有物理算法和原生状态。

| 环节 | Core 提供 | Adapter 至少返回或保证 |
| --- | --- | --- |
| 查询 | 执行选择、具体任务／资产、控制／观测／render／batch 需求 | 可用条件、版本／设备／solver／耦合范围、缺失项和原因；声明不等于原生验证 |
| 构建 | 统一场景、已准备资产、物理模型及解析配置 | 构建身份、实体／关节／控制映射、实际配置、转换与限制；失败关闭已创建资源 |
| 初始化／reset | Core 采样、seed、环境选择和容差 | 实际状态、采样与执行身份、时间基准及偏差；不隐式重采样 |
| 控制与步进 | [物理命令](control-and-feedback.md)、作用区间、完成要求 | 接受／限幅／拒绝、实际推进区间、完成状态、部分执行与异常 |
| 状态发布 | 消费者必需／可选字段、布局与同步需求 | 类型、单位、坐标、语义映射、时间和有效期；读取成本与设备明确 |
| 关闭／失败 | [生命周期操作](lifecycle-and-data.md) | 释放拥有的资源、使旧数据失效、报告清理结果；共享进程级资源按 owner 协调 |

接口不要求所有 provider 提供所有物理量。任务或 Controller 的必需需求不能满足时拒绝该组合；可选字段缺失须明确可用性。控制回执不等于关节力测量，接触事件不等于接触力。

## 查询与准入

查询应区分原生 API 支持、adapter 实现、已验证范围、依赖不可用及已知不支持。对具体任务、source、设备、solver、renderer 和 batch 求交集，不能只判断 provider 名称。用户配置可收紧声明，不能自行扩权。

适配范围包括刚体／非刚体族、关节与约束、执行器与传动、必需耦合、控制／观测反馈、reset 粒度、共享场景和数据传输。资产准入遵循[统一表示](unified-task-representation.md)，不得以“格式支持”替代具体语义检查。

已知缺失应尽可能在昂贵初始化前报告。只能在原生编译后核实的限制，应在该处拒绝并清理；不能承诺仅靠静态查询证明运行正确。错误信息附请求、失败阶段、缺失能力、实际身份和可采取的配置行动。

## 时间、状态与并行

- 分开物理步长、内部 substep、Controller 更新周期、外部 step 和图像采样；精确时间表示沿用既有 timebase。
- 异步 native 推进可返回公开完成凭据，由 session 协调等待；状态／采样消费者不得读到未完成写入。
- 状态按需求公开；host copy、设备视图或转换缓冲区均可，须明确只读性、所有权、布局和失效边界。
- 标量、原生 batch、同构／异构场景、部分 reset 和进程并行分别声明。原生批次统一执行配置，切换时整批重建。
- 原生 ID、私有 solver field 和全局进程状态不能直接成为任务 API。Renderer 如复用原生资源，走[共同构建与绑定](render-provider.md)。

## 转换和失败

质量／惯性／坐标／传动或 solver 参数转换必须可追溯；无法保持任务必需语义时拒绝。原生驱动适配的已接收例外保持原范围，不把本协议变成严格源等价研究。

部分推进后失败不能假装整步未发生，也不能返回正常 transition；保存已知完成区间和错误，按生命周期进入不可 step 的状态直至 reset 或 close。不要求跨后端保存／恢复内部 solver state，也不保证 reset 切换失败后继续旧 episode。

1c 须冻结最小必需反馈、能力状态枚举和错误结构，并把三条真实首批路线逐项映射到现有 owner；3a–3c 才实施和验证其运行能力。
