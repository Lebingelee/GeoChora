# 统一任务表示协议草案

状态：`DRAFT_FOR_DISCUSSION`；1b 冻结。本文规定责任和语义，不预定新增类名、schema 版本或生产 API。实现前对照[源码 owner](../planning/source-map-and-references.md)，复用已有 Artifact、Scene、TaskDefinition、source 和 ExecutionSpec。

## 四类信息

| 信息 | Core 应表达 | Adapter 消费与反馈 |
| --- | --- | --- |
| 任务语义 | 稳定实体身份、关系、初始化规则、动作／观测要求、任务参数 | 绑定可公开读取的原生对象；不接管奖励、成功条件和 Solution |
| 物理模型 | 刚体／可变形体／绳索／粒子／连续介质类型，材料、约束、边界条件及实体间必需作用 | 声明能表达的模型和耦合；给出原生构建及转换结果 |
| 资产表示 | 来源与内容身份、依赖闭包、视觉／碰撞／物理离散表示、各表示映射 | 校验具体输入，报告采用的表示、映射和无法保留的语义 |
| 执行配置 | provider、宿主、物理引擎、solver 组合、coupler、设备、精度、时间步、并行布局和 render 选择 | 返回实际生效配置和限制；不能静默 fallback |

同一逻辑实体可以有多种表示，几何文件格式不决定全部物理能力。刚体参考点／惯性系／视觉局部坐标等映射必须明确；provider 整数索引留在 adapter 内部。Core 的语义身份、版本与来源绑定不随 native 排序变化。

## 执行层级

路由应能区分：独立 MuJoCo、独立 GeoPhys、独立 Newton，以及以 Isaac Sim 为宿主、PhysX 或 Newton 为物理引擎的路线。solver 族、具体算法、耦合和设备为独立信息，不能把任意字符串层级强加给所有项目；不适用项显式表示，不伪造中间层。

一个 provider 负责整场景的物理推进，并拥有内部求解器与耦合。支持刚体和软体两类实例，不证明支持它们相互接触。跨 provider 交换力／状态不属于本版协议实施范围。

## 需求、编译与身份

1. 任务声明必需和可选的控制、状态、sensor、物理相互作用及 reset 能力。
2. Core 汇总 physics、Controller、renderer 的构建需求和资源约束，按既有优先级解析配置一次。
3. Adapter 对具体资产与配置进行能力检查，再执行声明的原生编译。
4. 编译结果绑定原任务／source 身份、原生对象映射、实际配置、转换项与限制；编译成功不替代初始化或步进验证。
5. 构建所得环境固定 observation 契约；允许的 reset 执行选择须仍能满足它。新配置产生新执行身份，旧接收不自动转移。

任务语义可以引用 provider-neutral 的类型化扩展需求，adapter 也可暴露有命名空间的原生选项。未知选项、影响物理含义的未处理字段与不兼容扩展必须拒绝，不能吞掉配置。

## 资产准入

| 层次 | 必须核实 |
| --- | --- |
| 可读取 | 文件、引用依赖、内容身份和必要扩展完整 |
| 可表达 | 材料、约束、离散模型、执行器和必需相互作用被当前路线支持 |
| 可初始化 | 单位、质量、惯性、边界条件、初始状态及实体映射符合声明 |
| 数值有效 | 在任务约定运行范围内，通过有 oracle／容差依据的检查；NaN 检查只是一部分 |

1a/1c 冻结本版刚体输入的具体量和检查成本。Adapter 报告无法从公开 API 测量的项为 `NOT_MEASURED`；任务必需项无法证明时不得准入。允许单位或索引转换，但必须记录。改变网格、物理模型或材料含义的适配须显式产物与身份，未来由 asset harness 组织。

## 非刚体准备

类型与引用边界应允许变形顶点、粒子、场、绳索节点、材料参数、边界条件、视觉映射与拓扑代次。不能把所有状态压成 CPU 定长向量，也不能要求无关任务必须有 joint action 或接触力。

本版用契约正／负例证明扩展位置与拒绝规则；不虚构完整软体／流体 DSL，不要求同时真实运行这些模型。具体字段在真实任务与公开能力出现时扩展。
