## 一、需求与边界

在控制器配置中提供是否使用重力补偿的明确选项：

- **关闭为默认值**，保持现有控制语义、动作空间、旧配置和既有受支持路径的行为；新开关如何进入版本化配置与 identity、默认值是否保持历史哈希，需要按现有兼容合同在设计阶段核实，不能假定添加字段天然不改变旧身份。
- 开启时仅计算**被选机械臂本体**的重力负载，包括模型中属于该机械臂且由所选驱动链支撑的 link、末端及手爪自身；具体刚体集合、固定连接与手爪配置必须由 source/Artifact 明确绑定。桌面、场景物体和夹持物等外部负载不纳入本次补偿，也不将接触、碰撞或物体反作用力称作本体重力。
- 固定基座的**任意有效世界旋转**都必须正确处理，不得假设基座竖直或世界重力总在基座局部负 Z。设计目标是在所声明可行工作范围内保持目标位姿稳定；关节限位、力矩饱和、碰撞、数值病态或模型参数错误等情况下不能承诺无条件稳定。
- 首次控制边界应基于 reset 后已经测得的 q、当前基座姿态和场景重力计算补偿，而不是必须等 TCP 下沉后再建立支撑力矩；不能通过隐式新增物理步或未声明的 settle 来掩盖启动瞬态。
- 本次要求固定基座的任意旋转；运动基座、非惯性加速度、外物载荷补偿、动力学前馈和安全认证均不在已确认范围。后续如需扩展须另行设计和验证。

## 二、已有证据与解释

1. **历史边界。** 3a 接收为路由／准入，不是 TCP 零漂移接收。3b 配对对照中，3a 接收后代码（`0192f2ec`，相对 `44e8d00f` 仅文档变化）与 3b 输入 `470c3ef9` 在 MuJoCo、相同 PickCube seed31、reset、source、控制器参数与动作下，11 个边界的 q、qdot 和 TCP 一致；原 N08 上移段两者均为约 −1.230 mm，原门仍 FAIL。这是该配置的回归证据，不外推其他后端或所有动作。原始匹配结果保存在阶段3工作目录 `workspace/maintenance/v211_g03_3b_attempt002/causal-comparison.json`，具体协议与限制见 [3b 返工分析](stage3-3b-rework-analysis.md)。
2. **阶段2成功记录。** 旧 NutAssembly MuJoCo CPU seed19 成功 H5，源码 `92094493`，2,377 transitions；整条轨迹 TCP 位置误差 RMS 约 1.253 mm。当前输入 `470c3ef9` 的 467-transition NutAssembly 对照中，468 个边界的 q、qdot、TCP 位姿及逐步目标与该旧记录一致，但 controller identity 不同；此结果不能推及整条任务。旧记录输入 SHA-256 为 `b2db11aa48a2d743464b9ca390131fba659a697a554432a5c118106e4c5c74e9`。成功运行开始阶段亦有约 3 mm TCP 下沉；某些后续固定目标阶段存在小于 0.01 mm 的误差。保持目标在阶段切换时可能由实测位姿初始化，不能把该数值泛化为任意外部目标或全程精度。
3. **恒定初始位姿实验。** 2026-11-06，当前工作树、NutAssembly MuJoCo CPU、seed19，以 reset 实测 TCP 世界位姿和初始开口作为恒定目标，5 s／500 control steps、10 ms control／2 ms physics ×5。TCP Z 相对 reset 在 0.17 s 最低约 −3.025687 mm；0.96 s 最高约 +0.048884 mm；从 1.34 s 到 5 s 的已记录 10 ms 采样点均在 ±0.01 mm 内。5 s 终值相对原始 reset Z 约 +0.000014 mm，与 float32 动作目标舍入误差相当。此为单配置实测而非全基座姿态保证。
4. **启动与稳态力矩。** 同条件复跑 TCP Z 逐采样与上项完全一致。首个 2 ms 物理子步 qdot 为零，实际驱动力矩近零；同姿态零速度的重力 bias 约 joint2 −15.064、joint3 −4.292、joint4 +21.506、joint5 +0.636、joint6 +2.289 N·m；首子步这七个臂关节上的求解器约束广义力为零。约 5 s 时对应驱动力矩约 −15.061、−4.294、+21.506、+0.636、+2.289 N·m，与静态 bias 一致。以 joint4 为例，稳态驱动目标与实际位置差约 +0.0061445 rad，刚度 3500 N·m/rad，给出约 21.506 N·m。目标是伺服位置而非直接力矩；TCP 误差接近零时，关节伺服位置差仍可保持非零。
5. **证据权限与限制。** 上述力值来自独立诊断进程对 MuJoCo `mj_step` 的只读拦截及同模型 scratch `MjData` 的零速度 bias 重算，并非 TaskEnv 目前正式公开的七关节力回执。该诊断访问求解器层，仅作为历史定位证据，不构成生产接口设计先例；实现和验收必须经正式 source/model/runtime 公共契约，不依赖 provider 私有状态。力矩、bias、约束、被动项及采样时点须区分，不能把 bias 符号直接写成重力外力符号。

## 三、已定位的机制与未决问题

当前 R3 首次以实测 q 初始化持续关节参考，通过目标 TCP 与实际 TCP 的误差形成期望速度，经 Jacobian/DLS 及限幅积分更新关节参考；固定位置目标的速度前馈初始为零。现有 MuJoCo Panda 位置驱动通过位置偏差与阻尼生成执行力矩。在该 Nut 实验的第一物理步，目标近似当前 q、qdot=0，故初始执行力矩近零，重力 bias 未被预先抵消；运动后反馈形成目标／实际差，最终在 TCP 误差很小时维持重力平衡。

该因果链受单后端、单姿态和观测精度约束；不要表述为所有漂移均由重力造成。需要澄清模型质量、COM、关节轴与重力惯性坐标来源及其 provider 一致性；确定已加载工具、手爪及组合体各部件的本体边界；并区分 reset/first control 对齐、接触、传动、执行饱和和动态响应。

## 四、建议设计路线（需实施前审阅）

1. **定位与复用。** 沿现有 configuration、Controller/Position profile、source/Artifact、runtime capability/admission 和 provider adapter owner 检查实际调用链。配置与贡献组织优先 EXTEND_EXISTING／COMPOSE_EXISTING；不把重力逻辑写进 Nut/PickCube Solution，不新增平行 Controller、物理步进器或 Recorder。当前方案是否必须进入已规划的 4a typed JointEffort／contribution composition，由维护者及 Sol 决定；现有位置目标的贡献机制不应被假定已支持力矩叠加。
2. **配置与关闭兼容。** 定义具名、版本化、默认关闭的开关或模式；传递有效值至已存在的 selected configuration 和运行回执，执行前明确对象、frame、单位、作用范围。关闭时用实际受影响路径证明原动作、q/qdot、TCP、时间、原有 H5/schema 和失败行为保持；评估独立新 identity 与旧序列化兼容，不倒改冻结证据。
3. **本体动力学来源。** 基于经验证的 source 取得每个所选 robot body 的质量、局部 COM、关节类型/轴、树结构和固定变换；校验有限性、单位、父子关系、基座旋转与来源 identity。冻结 robot 本体集合及手爪／末端载具归属，排除动态外物。不在控制器依赖某后端私有 solver；缺公开信息应在 admission 明确拒绝或报告 NOT_SUPPORTED，不应静默按关闭继续运行。
4. **坐标与数学。** 从环境的世界重力向量 `g_world` 和旋转 `R_world_base` 构造 `g_base = R_world_base^T g_world`，结合当前各关节位置和机器人本体质量与 COM 计算 `tau_g(q, g_base)`；用明确定义的广义力符号、动力学方程和 Nm 单位统一接口。也可使用世界坐标算法，但必须通过坐标等价性验证。不得把固定的世界 −Z 原样当作任意旋转基座的局部 −Z，也不得把零速 bias 混同于包含速度项、约束项或外物的完整逆动力学。
5. **贡献与执行。** 首选按实际能力使用正式 JointEffort/贡献合成合同：重力、控制反馈与其他贡献明确组合，防止重复补偿，并保留驱动边界和实际 applied 回执。若某 provider 只能位置伺服，须先评估位置目标偏移方案的刚度、阻尼、传动比、饱和、稳定性和原控制器目标语义，不能把 `tau/Kp` 当成通用精确方案或未经论证混用力矩/位置。能力不具备、参数不可证或配置矛盾时明确拒绝；夹爪力限制不因臂补偿被绕过。不得通过私有 solver 访问绕过公开接口。
6. **观测与可追溯性。** 记录开关、来源 identity、本体集合、gravity/base rotation、计算时点、各具名关节 `tau_g`、合成/限幅后的目标或已施加贡献、单位和故障状态；目标、实际执行回执与实测反馈分列。既有记录路径扩展需考虑 schema 兼容；不能将计算值冒称传感器测量值。

## 五、后续验证建议（阈值须冻结后执行）

- **离线数学／帧验证：** 零重力输出为零；单连杆解析力矩、符号与单位；独立逆动力学或势能有限差分交叉校验；对同一物理场景在多个基座旋转下验证世界／基座表示等价；覆盖非对称惯量和至少一种非平凡转轴。单测不能代替真实 provider。
- **关闭回归与开启正例：** 沿当前公开 Nut seed19 初始位姿保持动作，先关闭再开启，记录 reset、首个控制边界、首个已施加物理采样和后续收敛；先比较同一 source/config 的确定性闭环与施加回执，再对齐关闭前的现有基线。测试阈值与采样时序在执行前按需求独立冻结，不能用本次结果事后改判据。
- **有代表性的基座姿态：** 身份旋转、绕 X/Y/Z 的非零旋转及组合旋转，尤其测试使世界重力在基座坐标中具有多个分量的姿态；在合法可达、力矩／关节约束可行、无意外接触的状态下比较 TCP 和关节状态。有限矩阵仅验证所测点；“任意旋转”还需数学坐标等价性与边界条件一起支持。
- **只算本体：** 同一机器人本体下改变场景外物质量／有无接触，纯计算 `tau_g` 不因外物被合并而改变；被夹持外物造成的实际下沉不得宣称已补偿。覆盖空手爪与本体手爪不同开度、若模型允许不同本体质量参数。
- **拒绝与安全：** 缺质量/COM/轴/基座姿态/重力、不可用 source 身份、驱动不支持、力矩/目标限幅、重复补偿和非有限数据；检查关闭态向后兼容、fault 与记录行为。验证饱和被明确报告且不宣称姿态保持通过。
- **后端范围：** 先在 MuJoCo 路线形成可复核的同配置证据，随后仅对实现实际支持的 GeoPhys/Isaac 路线分别验证公开能力、单位、base frame、reset 时序和 applied/readback；缺 API 保持 NOT_SUPPORTED/NOT_RUN。模拟器短时实验不自动构成真实机器人能力或 Qualification。
