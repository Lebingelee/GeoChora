# TaskEnv 资产导入与二次开发

本文面向需要添加 world、robot 或 object 资产的开发者。先按[安装与启动指南](../../docs/module/task_env/v2.1.1/guides/installation-and-start.md)准备对应源码和资产；[声明式任务示例](自定义任务构建指南.md)展示已有 Panda/table/box 组合。assembly 编译声明和 references，runtime 消费准入后的模型；资产登记或可导入本身不证明任意 provider 可以运行。

## 当前结构

~~~
registry.py                 # component 与 environment registry
tasks/worlds/               # scene/world 描述
robots/                     # robot/agent 描述
objects/                    # object 描述
assembly/                   # source compile、MJCF、references
controllers/                # public action 到 control command
runtime/                    # physics lifecycle boundary
observations/               # observation/sensor projection
tasks/                      # task composition 与 task semantics
planners/                   # public trajectory primitives
recorders/                  # public transition/H5 recording
render/                     # selected-world rendering adapters
~~~

推荐顺序是：asset definition → Task entity instance → source snapshot/closure → Robot recipe/TCP/传动 → Controller 匹配 → Task binding → reset/step/close 证据。静态声明和来源可复现先于物理声明；渲染和训练各按独立能力验证。

## 导入 object

1. 在 objects/ 创建 BaseTaskObject 子类，并用 register_object("object-v1") 注册。
2. asset_manifest() 声明本地 source、asset roots 和版本；可选补充稳定 source reference/revision。procedural asset 还应记录 generator/version 与规范化参数。构造 manifest 不读取磁盘，也不证明 importer 消费了特定字节；逐次来源闭包摘要与 importer/canonical 映射属于导入 Evidence。reference_spec() 列出 task 会使用的 body/joint/site/geom/actuator 名称。
3. 保持局部坐标、质量、惯量和 collision/visual geom 的单位一致；不要在 object 类中缓存 compiler 产生的 qpos index、body id 或 contact slot。
4. 为新 object 添加 assembly 和短步进 smoke；如果存在 MuJoCo/reference，使用相同初态、dt 和单位对照 pose/joint/site。

## 导入 robot

robot 除了 asset manifest/reference，还需要 agent contract：joint、qpos、dof、actuator、hand body 和 TCP/site 名称必须能在 assembly 阶段一次解析。controller 只把 public target 转成 control command，不复制动力学，也不读取 solver private field。

相关 importer 和 runtime 有串联关节、direct actuator、fixed tendon、primitive/mesh 等路径，但支持取决于实际资产、provider、backend 和准入；不能由此推断任意组合稳定支持。遇到 site/body/slidercrank actuator、spatial tendon、复杂闭链或未支持 MJCF 元素，应在对应导入或准入边界明确拒绝或写出诊断，不静默降级。

## 接入 task 与渲染

资产通过 assembly 验证后，在 tasks/<task_family>/composition.py 中组合，并由 task definition 消费 public snapshot。相机/传感器通过 observations/ 接入；并行渲染通过公开 RenderAssemblyDesc 或 RenderSceneDesc 提供 asset table 和 body transform，不把 Go2 或其他任务私有规则放回通用 renderer。

录制器只消费 public reset/step/info/metadata。runtime、solver、Taichi field、asset cache 和渲染 backend 的 private layout 不属于 task 或 recorder API。

## 常用注册 API

| 目标 | API | 说明 |
| --- | --- | --- |
| robot 注册 | register_agent("robot-v1") | 提供 agent component 和 reference contract |
| object 注册 | register_object("object-v1") | 提供 object component 和 asset manifest |
| world 注册 | register_scene("world-v1") | 提供 scene builder 和 world asset |
| 资产声明 | asset_manifest() -> AssetManifest | 本地 source/root、owner、version；可选稳定 source reference/revision 或 procedural generator 元数据 |
| 引用声明 | reference_spec() -> ReferenceSpec | body/joint/site/geom/actuator 名称 |
| 初始状态 | initial_state_spec() -> InitialStateSpec | robot 初始关节状态 |
| action 能力 | supported_action_modes() | public action mode 列表 |
| 编译场景 | compile_task_scene(...) | 生成 compiled scene 和稳定 references |

这些数据契约位于 task_env.environment.protocols 和 task_env.environment.types；完整签名见 API Reference。

## 验证清单

- asset source、reference name 和 package-data 在干净环境可定位；
- scene compile 能对未知引用明确报错；
- FK/site pose、qpos/qvel、controller 单 tick 和 reset 通过；
- 需要并行时补充 batch slot isolation、masked reset 和 action shape smoke；
- 需要渲染时补充 headless RGB smoke；
- 有 MuJoCo/reference 时记录同初态、同 dt 的误差和差异原因。

## 从现有声明到共同绑定

对象 `asset_manifest()` 描述资产来源，Task Artifact 中的 entity 实例提供自己的语义身份和初态；一个定义可用于多个实例，但不能把 source 中的 native ID 视为跨重建稳定值。Panda 的 Robot recipe 提供 frame、joint、传动、TCP、writer 和支持的 Controller；Task 声明所需 body/site 映射，公共 composer 绑定同一 source，Controller 校验语义、单位与资源后消费该 source，`RobotRuntime` 才显示已绑定主体。默认 Controller 初始未绑定，显式支持的 profile 不能被它替换。

下面只检查 Nut 资产声明，不下载或修改资产；注册与声明不是物理执行证据：

```python
from task_env.objects.nut_assembly import SquareNutObject

nut = SquareNutObject()
manifest = nut.asset_manifest()
references = nut.reference_spec()
print(manifest.source_reference, manifest.source_revision)
print(references.body_names, references.joint_names, references.site_names)
```

文件来源、引用闭包、几何尺度（m）、质量（kg）、惯量及碰撞/visual 几何应随 source 核查；不要手填 source hash 或从 provider 私有 state 推断绑定。错误名称/缺失资产应在构建时拒绝，异常也须释放 source。实际操作从[声明式 marker](自定义任务构建指南.md)开始；本轮只验证 MuJoCo CPU 的既有 Panda/table/box，不授权分发外部资产或推断任意 Robot/provider 支持。
