# TaskEnv 资产导入与二次开发

本文面向需要添加 world、robot 或 object 资产的开发者。资产描述只在 CPU 侧 assembly/compile 阶段存在，runtime 只消费编译后的稳定数组和 references。

## 当前结构

~~~
registry.py                 # component 与 environment registry
worlds/                     # scene/world 描述
robots/                     # robot/agent 描述
objects/                    # object 描述
assembly/                   # source compile、MJCF、references
controllers/                # public action 到 control command
runtime/                    # physics lifecycle boundary
observations/               # observation/sensor projection
tasks/                      # task composition 与 task semantics
planners/                   # public trajectory primitives
recorders/                  # public transition/H5 recording
render/                     # selected-world rendering adapters
~~~

推荐顺序是：asset manifest → reference contract → assembly compile → reset/step smoke → task composition → controller/observation/render。

## 导入 object

1. 在 objects/ 创建 BaseTaskObject 子类，并用 register_object("object-v1") 注册。
2. asset_manifest() 声明真实 source、asset roots 和版本；reference_spec() 列出 task 会使用的 body/joint/site/geom/actuator 名称。
3. 保持局部坐标、质量、惯量和 collision/visual geom 的单位一致；不要在 object 类中缓存 compiler 产生的 qpos index、body id 或 contact slot。
4. 为新 object 添加 assembly 和短步进 smoke；如果存在 MuJoCo/reference，使用相同初态、dt 和单位对照 pose/joint/site。

## 导入 robot

robot 除了 asset manifest/reference，还需要 agent contract：joint、qpos、dof、actuator、hand body 和 TCP/site 名称必须能在 assembly 阶段一次解析。controller 只把 public target 转成 control command，不复制动力学，也不读取 solver private field。

当前稳定支持边界包括串联 HINGE/SLIDE/UNIVERSAL、direct joint actuator、fixed tendon actuator、primitive/mesh link 和基础接触。遇到 site/body/slidercrank actuator、spatial tendon、复杂闭链或未支持 MJCF 元素，必须在 compile 阶段明确拒绝或写出诊断。

## 接入 task 与渲染

资产通过 assembly 验证后，在 tasks/<task_family>/composition.py 中组合，并由 task definition 消费 public snapshot。相机/传感器通过 observations/ 接入；并行渲染通过公开 RenderAssemblyDesc 或 RenderSceneDesc 提供 asset table 和 body transform，不把 Go2 或其他任务私有规则放回通用 renderer。

录制器只消费 public reset/step/info/metadata。runtime、solver、Taichi field、asset cache 和渲染 backend 的 private layout 不属于 task 或 recorder API。

## 常用注册 API

| 目标 | API | 说明 |
| --- | --- | --- |
| robot 注册 | register_agent("robot-v1") | 提供 agent component 和 reference contract |
| object 注册 | register_object("object-v1") | 提供 object component 和 asset manifest |
| world 注册 | register_scene("world-v1") | 提供 scene builder 和 world asset |
| 资产声明 | asset_manifest() -> AssetManifest | source、root、owner、version |
| 引用声明 | reference_spec() -> ReferenceSpec | body/joint/site/geom/actuator 名称 |
| 初始状态 | initial_state_spec() -> InitialStateSpec | robot 初始关节状态 |
| action 能力 | supported_action_modes() | public action mode 列表 |
| 编译场景 | compile_task_scene(...) | 生成 compiled scene 和稳定 references |

这些数据契约位于 task_env.environment.protocols 和 task_env.environment.types；完整签名见 API Reference。

## 验证清单

- asset source、reference name 和 package-data 在干净环境可定位；
- scene compile 能对未知引用明确报错；
- FK/site pose、qpos/qvel、controller 单 tick 和 reset 通过；
- 需要并行时补充 batch slot isolation、masked reset 和 action shape smoke；
- 需要渲染时补充 headless RGB smoke；
- 有 MuJoCo/reference 时记录同初态、同 dt 的误差和差异原因。
