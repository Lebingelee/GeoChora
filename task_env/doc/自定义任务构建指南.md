# 自定义 TaskEnv 任务

本文面向需要在 task_env/tasks/ 中创建新 task family 的开发者。任务代码拥有场景组合、episode reset 和任务语义；公共 runtime、controller、lifecycle 和并行适配由框架负责。

## 目录职责

~~~
task_env/tasks/<task_family>/
├── spec.py          # UID、资产清单、action mode、任务配置
├── env.py           # BaseTaskEnv 注册和组件装配
├── composition.py   # task-owned world/object placement
├── reset.py         # 可选：reset sampler 与随机化
├── definition.py    # observation、reward、success、failure、metrics
└── solution.py      # 可选：只通过 public action/env.step 的任务策略
~~~

可以参考现有 pendulum.py、two_wheel_balance.py、pick_cube/ 和 nut_assembly/。不要复制 batch runtime 或 solver 实现到 task 目录。

## 最小实现步骤

1. 在 spec.py 选择新的 *-v1 UID，声明 scene、robot/object 依赖和 action mode。
2. 在 env.py 注册 BaseTaskEnv 子类，实现 create_scene_composer()、create_reset_sampler()（如需要）和 create_task_definition()。
3. 在 composition.py 通过稳定的 TaskReferences 声明对象放置，不要把 MJCF 顺序、qpos 地址或 body id 写成常量。
4. 在 definition.py 实现统一的 state view、observation、reward、success、failure 和 metrics。batch task 使用同一份任务语义，按 slot 返回数组。
5. 先用 make_env(new_uid) 完成 reset/step smoke，再根据任务是否满足 framework capability 添加 register_parallel_env()。
6. 最后再加入 planner、solution、render 或 learner 集成；这些不是 task 最小闭环的前置条件。

## 任务契约

- observation_space 和 action_space 是 shape/dtype/bounds 的唯一公开依据。
- terminated 表示任务成功或失败；truncated 表示 horizon，不能混用。
- info["is_success"]、task_metrics、reward_terms 的 key 在一个 episode 内保持稳定。
- task 只能通过 env.step(action) 推进仿真，不能访问 env._runtime、solver、Taichi field 或 action adapter private state。
- 需要增加 controller、universal action 或 H5 字段时，先建立跨 task 公共契约，不在单个任务里写隐式特例。

## 并行能力

并行环境是可选能力：

~~~
from task_env import make_parallel_env, register_parallel_env

@register_parallel_env("my-task-v1")
def build_parallel_spec(*args, **kwargs):
    raise NotImplementedError

env = make_parallel_env("my-task-v1", num_env=8, backend="cpu", execution="local")
~~~

注册函数只声明 task-owned parallel capability，不持有 runtime、solver 或 device field。真正的 batch lifecycle、masked reset、SB3 bridge 和 local/remote 选择由 task_env.vectorization 处理。

## 最小验证

~~~
PYTHONPATH=GeoPhys/src:. python - <<'PY'
from task_env import make_env

env = make_env("my-task-v1", config={"runtime": {"backend": "cpu"}})
try:
    observation, info = env.reset(seed=73)
    observation, reward, terminated, truncated, info = env.step(
        env.action_space.sample()
    )
finally:
    env.close()
PY
~~~

随后补充 task-specific reward/observation、reset boundary、parallel slot isolation 和 MuJoCo/reference 对照测试。未支持的 asset、actuator、tendon 或闭链能力必须在 compile 阶段明确拒绝，不能静默降级。
